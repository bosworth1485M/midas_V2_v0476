Do NOT modify any other scenario. Do NOT change any existing fields.

IMPORTANT ARCHITECTURE REALITY (do not ignore)
backtester.py runs symbol-by-symbol (for sym in symbols) and bar-by-bar per symbol. There is no global time loop across symbols.
Therefore: implement the day gate as a SINGLE PREPASS over the universe BEFORE the main trading loop, not as a time-synchronized cross-symbol loop.

DAY GATE BEHAVIOR (STRICT)
- If require_day_follow_through is false: behavior must be identical to prior versions (no change).
- If require_day_follow_through is true:
  1) Evaluate the day gate exactly once per run/day (ONE prepass).
  2) Compute follow-through count across the same universe list loaded from universe_path.
  3) If count < day_follow_through_min_symbols -> day_gate_failed = True (sticky)
     Else -> day_gate_passed = True (sticky)
  4) When day_gate_failed is True, block ONLY NEW ENTRIES for the rest of the day.
     - Do not interfere with managing open positions (TP/SL logic remains unchanged).
     - Do not modify strat.should_enter() or any strategy logic.

FOLLOW-THROUGH TEST (v1 minimal)
At the evaluation index i_eval = day_follow_through_minutes:
A symbol counts as “follow-through” if EITHER:
- close > vwap_at_i_eval
OR
- candle is green with body >= green_body_min
Where:
- close is bars[i_eval].c
- green candle means bars[i_eval].c > bars[i_eval].o
- body fraction is abs(c - o) / max(1e-9, (h - l)) and compare to green_body_min (if green_body_min is None, treat as 0.0)

VWAP COMPUTATION (minimal; local helper in backtester.py)
Compute VWAP up to i_eval using bars[0..i_eval] with volume weighting:
- typical_price = (h + l + c) / 3.0
- vwap = sum(typical_price * v) / sum(v)
If sum(v) <= 0 or missing values: treat VWAP as None and that condition fails closed (i.e., only green-body can qualify).

EDGE CASES (defensive)
- If a symbol has fewer than i_eval+1 bars, it cannot count as follow-through.
- If bars are missing fields, fail closed for that symbol.
- Use try/except defensively, but do not swallow the day-gate logs.

LOGGING REQUIREMENTS (MANDATORY)

These must occur before any entries are taken.
