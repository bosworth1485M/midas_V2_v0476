Short answer: usually it doesn’t matter, but there are a few gotchas.

Works with: Python, PowerShell, and most Windows APIs accept either \ or /. So
python scripts/run_day_simple.py … and python scripts\run_day_simple.py … both work.

Watch-outs:

CMD built-ins / some legacy tools treat / as an option switch (e.g., dir /w). Passing paths with / to those can misbehave.

A few older utilities expect backslashes only.

Best practice:

In docs for Windows, prefer backslashes \ to avoid edge cases.

In Python code, use pathlib (OS-agnostic) or forward slashes—Python normalizes them:

from pathlib import Path
p = Path("out/20250805/B/results_2025-08-05.csv")


Quote paths with spaces:

python "scripts\run day simple.py" --date 2025-08-07


For our runners and analyzers, either separator is fine; we document backslashes to be consistent with Windows conventions.
