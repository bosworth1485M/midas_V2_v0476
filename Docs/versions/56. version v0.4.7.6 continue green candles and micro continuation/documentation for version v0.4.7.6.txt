🧭 Midas_V2 v0.4.7.6 — Feature-Integration Architecture (Full Documentation)
1. Purpose of v0.4.7.6

This version formalizes the feature-integration architecture in Midas_V2.
It allows modular feature addition or removal — such as micro-continuation, Bollinger filters, or S/R logic — without editing core logic.
All features are controlled externally via sidecar JSON files and are OFF by default until enabled.

This version sets the foundation for fast, low-risk feature iteration:

Features can be smoke-tested in isolation.

Core components (strategy.py, backtester.py) stay stable.

Each new feature has its own sidecar and plug-in script.

2. Files / Scripts Introduced
File	Purpose

✅ Why This Is Safe

If the sidecar lists no enabled scenarios, the call immediately returns False (do nothing).

Any failure inside the plug-in automatically fails open (baseline preserved).

There is no performance impact if all features are OFF.

4. Micro Feature Logic — Overview
(a) Minute-Candle Filter

Requires rise_bars ≥ 3 consecutive green 1-minute candles with body ratio ≥ green_body_min (default ≈ 0.22 = 22%).
This ensures momentum before any micro check.

(b) Micro-Continuation Window

After a qualifying 1-minute bar, the plug-in fetches 1-second or 5-second data for a 60-second window.

It checks:

✅ Ratio of green micro-candles ≥ min_green_ratio (0.60 = 60%).

✅ EMA reclaim and/or VWAP hold (configurable).

✅ Allows a single brief pullback (allow_first_pullback=True).

(c) Decision Logic
Condition	Result
Continuation confirmed	Allow entry
Continuation fails	Block entry
No micro data / invalid timestamp	Skip check (baseline behavior)

6. How to Add a New Feature

Create a new feature file:
src\\midas_v2\\features\\<name>_feature.py

Add a matching sidecar:
config\\features\\<name>.json

Implement the plug-in pattern:

from midas_v2.features.registry import FeatureRegistry
def should_block_entry(scenario_id, symbol, bar, strategy):
    if not FeatureRegistry.is_enabled("<name>", scenario_id):
        return False
    # feature logic…
    return True_or_False


Strategy remains unchanged.
The one-line hook calls all active features automatically.
