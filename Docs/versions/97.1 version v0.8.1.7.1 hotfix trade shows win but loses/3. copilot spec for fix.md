BEGIN PURPOSE (EXACT)
Fix a confirmed execution correctness bug where trades labeled "TP" can produce negative PnL (and win-rate can be 100% while total PnL is negative).
This version restores internal consistency between:
- executed entry price
- TP/SL prices
- outcome labeling
- PnL calculation

This is an execution/accounting hotfix, NOT a strategy change.
END PURPOSE

BEGIN ROOT CAUSE FIX (REQUIRED)
Problem:
When post-entry expansion gate is enabled, TP/SL are computed at SIGNAL time (based on signal bar close),
but the actual entry happens later at CONFIRM time (based on confirm bar close). The code currently reuses TP/SL from signal time.
This can produce tp < entry and then TP outcomes with negative pnl.

Fix:
When POST_EXP confirms and we set the position, recompute TP/SL using the ACTUAL CONFIRM-TIME entry price.

Exact requirement:
- In the "pending_entry confirmed" branch (POST_EXP: CONFIRMED -> POSITION_SET),
  after setting `entry = bar.c` (confirm-time entry),
  compute: `tp, sl = strat.targets(entry)`
  and store those into position (and use those for position_set logging).
- DO NOT reuse pending_entry["tp"] and pending_entry["sl"] after confirmation.
- Keep qty from pending_entry["qty"] unchanged.

Add a WHY log line showing both old and new TP/SL so we can audit:
[WHY] v0.8.1.7.1 TP_SL_REBASE symbol=<SYM> confirm_time=<TS> entry=<ENTRY> old_tp=<OLDTP> old_sl=<OLDSL> new_tp=<NEWTP> new_sl=<NEWSL>

This rebase must occur ONLY at confirm-time entry creation.
END ROOT CAUSE FIX

BEGIN INVARIANT ENFORCEMENT (SAFETY NET)
Add correctness invariants at the moment a trade is closed:

Invariant A:
- If outcome == "TP" then pnl must be >= 0 (allow 0.00).
- If computed TP pnl is < 0, this is a correctness error.

Invariant B:
- If outcome == "SL" then pnl must be <= 0 (allow 0.00).
- If computed SL pnl is > 0, this is a correctness error.

Implementation:
- In the TP-close branch (pos_bar.h >= tp), after computing pnl:
  - if pnl < 0:
      - Emit a loud WHY log:
        [WHY] v0.8.1.7.1 OUTCOME_PNL_MISMATCH kind=TP pnl=<PNL> entry=<ENTRY> tp=<TP> qty=<QTY> bar_ts=<TS> symbol=<SYM>
      - Record the trade with a deterministic fallback outcome label: "ERR_TP_NEG_PNL"
      - Keep the pnl value as-is (do NOT flip sign); do NOT silently label as TP.
- In the SL-close branch (pos_bar.l <= sl), after computing pnl:
  - if pnl > 0:
      - Emit a loud WHY log:
        [WHY] v0.8.1.7.1 OUTCOME_PNL_MISMATCH kind=SL pnl=<PNL> entry=<ENTRY> sl=<SL> qty=<QTY> bar_ts=<TS> symbol=<SYM>
      - Record the trade with a deterministic fallback outcome label: "ERR_SL_POS_PNL"
      - Keep pnl value as-is.

Important:
- Do NOT change CSV schema. It is currently "symbol,outcome,pnl". Keep that.
- These ERR_* outcomes must still appear in the CSV so we can detect remaining corruption.

Goal of invariants:
- Ensure we never again count negative-PnL trades as TP wins.
- Make any remaining corruption explicit and auditable.
END INVARIANT ENFORCEMENT
