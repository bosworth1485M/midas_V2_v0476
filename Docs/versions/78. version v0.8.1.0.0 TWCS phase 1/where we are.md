3. TWCS (Trade-Window Candle Snapshot System) — Full Technical Design

(From your TWCS design file)


TWCS design

3.1 Purpose

TWCS provides the candle evidence needed to understand:

Why winning trades work

Why losing trades fail

Whether wicks, bodies, microstructure, VWAP slope, MACD slope aligned

Whether green streaks were strong or weak

Whether micro lower-highs signaled failure

This data becomes the foundation for:

VWAP slope filters

Weak third candle avoidance

Microstructure rejection detection

Adaptive sizing

Future DB analysis

AI-based trading pattern discovery

3.2 Output Files Per Trade

TWCS outputs four files per trade:

entry_snapshot.png                  (stub)
exit_snapshot.png                   (stub)
trade_snapshot_entry_meta.json
trade_snapshot_exit_meta.json


Stored under:

out/<YYYYMMDD>/<SCENARIO>/<SYMBOL>/snapshots/<TRADE_ID>/

3.3 Entry Window Specification

At the moment the strategy decides to enter, TWCS captures:

A. Macro (1-minute bars)

Last 10 minutes:

OHLC

Volume

Body %

Wick ratios

VWAP

MACD line / signal / histogram

B. Micro (1-second bars)

Last 60–120 seconds:

Micro HH/LL

Stalls

Thin volume

Micro pullbacks

C. Indicators

VWAP slope (bps)

MACD histogram slope

Green streak geometry

Spread & slippage snapshot

3.4 Exit Window Specification

At exit (TP/SL/EOD):

Next 3–5 minutes (1m bars)

Next 60–180 seconds (1s bars)

MFE / MAE

Outcome classification

3.5 Metadata Schema

Each JSON metadata file records:

Symbol

Scenario

Trade ID

Date

Window type

Entry/exit timestamps

Candles_1m

Candles_1s

Indicators

MFE/MAE

PnL

Outcome

3.6 Strict Polygon Key Handling Requirement

TWCS must follow exactly the procedure used in topgappers.py:

Load .env

Strip quotes

Reject missing key

Use Authorization: Bearer <key> header

NEVER use ...&apiKey= query parameter

This requirement ensures:

identical behavior

security

reproducibility
