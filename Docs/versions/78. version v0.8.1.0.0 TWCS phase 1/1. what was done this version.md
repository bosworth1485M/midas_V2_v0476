2.1 New module: src/midas_v2/dataio/polygon_loader.py

Purpose: centralize Polygon API key handling and provide simple helpers to fetch 1-minute and 1-second aggregates, using the exact same key semantics as scripts/topgappers.py (strip quotes, use Bearer header, no apiKey query param). 

polygon_loader

Key points:

Loads .env at project root (with override=True), safely:

If .env load fails, logs a [WARN] but does not crash imports.

load_polygon_key():

Reads POLYGON_API_KEY from environment.

Strips whitespace and surrounding quotes.

If missing, prints [ERR] POLYGON_API_KEY missing (set it in .env) to stderr and exits with sys.exit(1).

Tagged with # v0.8.1.0.0 comments.

polygon_get_json(url: str, key: str) -> dict:

Builds urllib.request.Request with headers:

Authorization: Bearer <key>

User-Agent: "midas_v2/1.0"

Uses urlopen with timeout=30.

Parses JSON and returns a dict.

On error: logs [ERR] with URL and exception and returns {} or re-raises (depending on implementation).

Aggregate fetchers:

fetch_agg_bars_minute(symbol, date_iso, key) -> dict

fetch_agg_bars_second(symbol, date_iso, key) -> dict

Build v2 aggs URLs:

/v2/aggs/ticker/{symbol}/range/1/minute/{date_iso}/{date_iso}

/v2/aggs/ticker/{symbol}/range/1/second/{date_iso}/{date_iso}

Important: no apiKey in the query string; only Authorization header.

__all__ = ["load_polygon_key", "polygon_get_json", "fetch_agg_bars_minute", "fetch_agg_bars_second"] so other modules can import cleanly.

This module is not yet used by TWCS, but is ready for future TWCS phases (minute/second bar fetching) and keeps key handling consistent.

2.2 New module: src/midas_v2/snapshots/twcs.py

Purpose: implement the core TWCS snapshot writer, responsible for:

Building the correct snapshot directory structure.

Saving entry and exit metadata JSON.

Providing placeholder stubs for future PNG rendering. 

twcs

Key behavior:

Module-level docstring references:

TWCS

v0.8.1.0.0

Side-effect-only, no data fetching

Public API:

build_snapshot_dir(root_out: Path, date_str: str, scenario: str, symbol: str, trade_id: str) -> Path

Converts date_str (e.g. "2025-08-01") → YYYYMMDD ("20250801").

Builds:
root_out / "20250801" / scenario / symbol / "snapshots" / trade_id /

Creates directories with parents=True, exist_ok=True.

save_entry_snapshot(snapshot_dir: Path, meta: Dict[str, Any]) -> None

Ensures snapshot_dir exists.

Writes meta to snapshot_dir / "trade_snapshot_entry_meta.json" using _write_json.

Calls _render_entry_png(snapshot_dir, meta) (stub).

save_exit_snapshot(snapshot_dir: Path, meta: Dict[str, Any]) -> None

Ensures snapshot_dir exists.

Writes meta to snapshot_dir / "trade_snapshot_exit_meta.json".

Calls _render_exit_png(snapshot_dir, meta) (stub).

Internal helpers:

_write_json(path: Path, data: Dict[str, Any]) -> None

Uses UTF-8, indent=2, ensure_ascii=False.

Wraps json.dump in try/except; on failure logs [ERR] and returns (no exception propagation).

_render_entry_png / _render_exit_png:

Placeholders; currently no-ops or simple [INFO] logs.

Prepare for future matplotlib-based snapshots.

All public functions use try/except to avoid backtest crashes; failures only produce [WARN]/[ERR] logs.

__all__ = ["build_snapshot_dir", "save_entry_snapshot", "save_exit_snapshot"] ensures clean imports.

3. What TWCS Phase 1 Achieved (Context For Next Version)

TWCS Phase 1 (today’s version):

Established directory layout for snapshots:

out/YYYYMMDD/SCENARIO/SYMBOL/snapshots/TRADE_ID/


Writes two metadata JSON files per trade:

trade_snapshot_entry_meta.json

trade_snapshot_exit_meta.json

Metadata includes:

symbol, scenario, trade_id, date.

entry_time / exit_time.

window_type: "entry" or "exit".

Placeholder arrays: candles_1m, candles_1s.

Placeholder indicators.

For exit: mfe, mae, pnl_raw, pnl_pct, outcome ("TP", "SL", or later "EOD").

Everything is controlled by twcs_enabled in Scenario B’s params.

Example snapshots are in the previous section.

Important: TWCS currently uses empty arrays for candles and indicators.
This is intentional; v0.8.1.0.0 is about structure, not data richness.
