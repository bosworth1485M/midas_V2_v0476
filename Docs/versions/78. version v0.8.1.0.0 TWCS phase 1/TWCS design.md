v0.8.1.0.0 introduces:

TWCS — Trade-Window Candle Snapshot System

TWCS will:

Capture pre-trade and post-trade candle windows around each trade.

Save metadata JSON files alongside each trade.

4. Detailed TWCS Design (Technical Spec)

This section is the pure design of TWCS. It’s the same conceptual blueprint you captured earlier, expanded and consolidated here. 

plan for candle printing

4.1 Purpose

TWCS exists to:

Show the actual candle structure before and after each trade.

Provide visual & structural evidence for:

Why losing trades fail

Why winning trades work

Capture key details:

Wicks

Bodies

VWAP slope

MACD behavior

Microstructure from 1-second bars

Become the ground truth for:

Wick rejection filters

Weak 3rd green filters

VWAP slope filters

Micro-lower-high filters

Stall candle detection

Future DB schema

AI-based pattern discovery

No numeric indicator alone can replace what the snapshots reveal.

4.2 TWCS Outputs per Trade

For each trade, TWCS will produce:

entry_snapshot.png (stub in this version)

exit_snapshot.png (stub in this version)

trade_snapshot_entry_meta.json

trade_snapshot_exit_meta.json

Under a directory:

out/<YYYYMMDD>/<SCENARIO>/<SYMBOL>/snapshots/<TRADE_ID>/


Where:

YYYYMMDD is the trading date (no dashes).

SCENARIO is e.g. "B".

SYMBOL is the ticker.

TRADE_ID is a unique identifier per trade (e.g. symbol + entry time).

4.3 Entry Window (Pre-Trade Snapshot)

At the moment the strategy decides an entry is valid, TWCS captures:

A. 1-minute bars (macro)

Last 10 minutes of 1-minute candles.

Data per bar:

Open, high, low, close

Volume

Body % of range

Upper/lower wick %

VWAP (if available)

MACD line/signal/histogram values

These define the macro structure of the breakout attempt.

B. 1-second bars (micro)

Last 60–120 seconds of 1-second candles.

Used to see:

Micro higher-highs or lower-highs

Stall candles

Micro pullbacks

Thin volume patches

This exposes micro entry quality.

C. Indicators

At entry, TWCS records:

VWAP

VWAP slope (bps)

MACD histogram and its slope over recent bars

Green streak bar count, and geometry of each streak bar

Volume vs previous minute

Spread & slippage snapshot

4.4 Exit Window (Post-Trade Snapshot)

At trade exit (TP, SL, or EOD flatten), TWCS captures:

A. 1-minute bars

Next 3–5 minutes of 1-minute candles.

B. 1-second bars

Next 60–180 seconds of 1-second candles.

C. Outcome metrics

PnL

MFE (max favorable excursion)

MAE (max adverse excursion)

Did the breakout truly continue after exit?

Did the stop loss correspond to real failure, or was it too early?

4.5 Metadata JSON Schema (Conceptual)

Each metadata JSON file contains:

{
  "symbol": "BTAI",
  "scenario": "B",
  "trade_id": "BTAI_2025-08-01T10:32:00",
  "date": "2025-08-01",
  "entry_time": "2025-08-01T10:32:00",
  "exit_time": "2025-08-01T10:36:30",
  "window_type": "entry",      // or "exit"
  "candles_1m": [...],         // structured 1m bars for this window
  "candles_1s": [...],         // structured 1s bars for this window
  "indicators": {
    "vwap": ...,
    "vwap_slope_bps": ...,
    "macd_hist": ...,
    "macd_slope": ...,
    "green_streak_bars": 3,
    "upper_wick_ratio_last": ...,
    "stall_candle_detected": false,
    "micro_lower_high_detected": false
  },
  "mfe_pct": 0.021,
  "mae_pct": -0.012,
  "pnl_raw": 35.0,
  "pnl_pct": 0.02,
  "outcome": "TP"               // or "SL" or "EOD"
}


Exact structure can be refined later; v0.8.1.0.0 focuses on:

4.6 Critical Requirement: Polygon Key Handling

TWCS will eventually need Polygon minute/second data. While in v0.8.1.0.0 we may still rely on local CSV, any TWCS-related Polygon access MUST replicate the topgappers.py pattern exactly.

From scripts/topgappers.py: 

topgappers

Load .env with override:

from dotenv import load_dotenv
load_dotenv(ROOT / ".env", override=True)


Load and sanitize POLYGON_API_KEY:

k = (os.environ.get("POLYGON_API_KEY") or "")
k = k.strip().strip('"').strip("'")
if not k:
    print("[ERR] POLYGON_API_KEY missing (set it in .env)", file=sys.stderr)
    sys.exit(1)


Use Authorization header:

req = urllib.request.Request(
    url,
    headers={"Authorization": f"Bearer {key}", "User-Agent": "midas_v2/1.0"}
)


Never do ...?apiKey=... or embed the key in URLs.

TWCS’s future Polygon loader module must copy this behavior exactly.
