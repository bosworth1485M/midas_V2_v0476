## Why August WR differs from earlier ~63%

1. **Universe drift (primary):** the earlier 63% came from a particular per‑day symbol set. Rebuilding the universe later (or using a different saved list) changes which tickers enter, moving WR and PnL.
2. **Analyzer inputs:** mixing `out/auto/...` artifacts previously inflated counts; the base‑only approach reads only the per‑day canonical files.
3. **Driver order:** summarizing before generating per‑day files yielded “0 trade” summaries. The safe driver fixes this by running days first.
4. **Scenario creep (minor):** even small param changes (gate, SL, MACD) can shift WR; we restored August‑baseline params for D/E before replays.

**Conclusion:** There is no engine bug; the difference is explained by **inputs (universes)** and **workflow (files/ordering)**. The base‑only + safe‑driver workflow now reproduces consistently.

## Glossary — terms we’ll use consistently

- **Canonical per‑day output ("canonical"):** the official per‑day results file the backtester writes:  
  `out/YYYYMMDD/SCENARIO/results_YYYY-MM-DD.csv`. All baselines & base‑only analyses read *only* these.
- **Base‑only analysis:** computing N / WR / PnL solely from canonical per‑day files (ignores `out/auto/...` and any other artifacts).
- **Raw top‑gappers:** the saved list for a date with **no catalyst filter**:  
  `data/universe_topgappers_YYYY-MM-DD.txt`.
- **Catalyst universe:** a filtered list written to  
  `data/catalyst/universe_YYYY-MM-DD.txt` (news‑scored, optional top‑N). Raw lists remain unchanged to support A/B testing.
- **Safe driver:** `scripts/run_range_safe.py`, which runs each day’s backtest first, then summarizes, so fresh sessions never produce “0 trade” summaries.
- **Universe drift:** differences in which symbols are in the day’s list (saved vs rebuilt) that change downstream results.
- **Auto artifacts:** helper outputs in `out/auto/...` (e.g., range summaries). Useful for reporting, but **not** inputs to base‑only calculations.
