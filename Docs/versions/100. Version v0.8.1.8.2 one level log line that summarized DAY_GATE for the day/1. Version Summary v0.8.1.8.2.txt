Version Summary — Midas_V2 v0.8.1.8.2
Purpose of This Version

v0.8.1.8.2 is a diagnostic and stabilization release.
Its purpose is to make day-level trading outcomes fully explainable while preserving identical trading behavior to the prior version.

Before this version:

Zero-trade days were common

The reason for those zero-trade days was implicit

Profit analysis was blocked by ambiguity at the day regime level

After this version:

Every successfully executed trading day emits a single, authoritative day-level summary

Day quality can be classified deterministically

Profit-affecting changes can now be introduced safely

Behavioral Clarification (Corrected)

Trading behavior remains identical to v0.8.1.8.1 — meaning:

entry logic is unchanged

exit logic is unchanged

trade count is unchanged

execution order is unchanged

PnL is unchanged

What did change in v0.8.1.8.2:

We now log the already-computed DAY_GATE counters (e.g. close_gt_vwap_cnt)

This enables day-level classification for observability only

The classification is diagnostic, not prescriptive

There is no new scoring system used by the strategy in this version.

What Was Implemented
1. DAY_GATE Day-Level Summary Logging

A new log entry is emitted once per trading day per scenario, after DAY_GATE evaluation and before per-symbol trading begins.

Format (single logical record):

[WHY] v0.8.1.8.2 DAY_GATE_SUMMARY
details=enabled=<bool>
gate_minutes=<int>
min_symbols=<int>
close_gt_vwap_cnt=<int>
require_close_gt_vwap=<bool>
day_gate_failed=<bool>


Properties:

Uses existing variables only

No new counters

Exactly one emission per day

Reflects the final gate state actually used

2. Logging Correctness Fix (Single-Record Guarantee)

During testing, the summary initially appeared as multiple physical lines due to a hidden newline inside the format string.

Fix:

Ensured the format string is a single continuous string

Verified via raw source inspection and fresh execution logs

Impact:

Observability only

No behavior change

3. Runtime Stability Fix (Discovered During Validation)
Bug — Missing post_entry_expansion_gate

Symptom (during 2025-07-18 run):

AttributeError: 'StrategyParams' object has no attribute 'post_entry_expansion_gate'


Cause:

Backtester referenced an optional parameter

Some restored configs lacked that field

Bug surfaced only on days with deep execution paths

Fix:

if getattr(strat.p, "post_entry_expansion_gate", False):


Impact:

Prevents crash

Preserves behavior

Defaults safely to False

Direction for the Next Version — v0.8.1.9.0

v0.8.1.9.0 will be the first profit-affecting version.

Agreed Policy Change
Day Classification	Behavior
close_gt_vwap_cnt == 0	Trade 0 (unchanged)
close_gt_vwap_cnt == 1	Allow exactly 1 trade (first valid signal)
close_gt_vwap_cnt ≥ 2	Unchanged
Why This Can Increase Profit

Marginal days already produce winning trades when allowed

Current policy discards them entirely

Limiting to one trade caps risk

Trade stats from healthy days show positive expectancy

This creates a measurable hypothesis:

Allowing one trade on marginal days should increase total profit without materially increasing drawdown.
