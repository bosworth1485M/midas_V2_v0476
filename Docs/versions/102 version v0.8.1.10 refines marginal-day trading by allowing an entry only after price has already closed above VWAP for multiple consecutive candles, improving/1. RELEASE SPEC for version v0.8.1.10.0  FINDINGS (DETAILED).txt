RELEASE SPEC / FINDINGS (DETAILED)
Midas_V2 v0.8.1.10.0 — Marginal VWAP Acceptance (2-bar pre-confirm)
Purpose (put first; explicit)

v0.8.1.10.0 refines marginal-day trading by allowing a marginal-day entry only after price has already demonstrated VWAP acceptance via two prior completed candles (i-2 and i-1) that are both:

green (close > open), and

closed above VWAP at that bar.

Goal: filter out “first close above VWAP” marginal entries that repeatedly fail (fast SLs), while preserving all previously correct behavior for hostile and healthy regimes.

Summary of what changed (software)
Files changed (only)

src/midas_v2/engine/backtester.py
No other files changed.
No config edits. No helpers. No refactors.

New rule added (high-level)

A new early-reject guard for Scenario B marginal days that runs only when:

DAY_GATE / day-follow-through is enabled (require_day_follow_through == True)

Day is marginal (close_gt_vwap_count == 1)

Marginal trade still available (day_trade_count < 1)

Entry is otherwise eligible (position None, pending_entry None, and effective_day_gate_failed == False)

Inserted between:

the existing DAY_GATE_FAILED early reject block, and

the combined entry condition that calls strat.should_enter(bars, i).

VWAP calculation requirement (implementation detail)

VWAP is computed incrementally using PV/V:

tp = (h + l + c) / 3.0

cum_pv += tp * v

cum_v += v

vwap_k = cum_pv / cum_v (if cum_v > 0)

Off-by-one clarification enforced: VWAP loop processes bars 0..i-1 using for k in range(i) so VWAP for i-1 is computed.

Reject behavior

If the 2-bar VWAP acceptance requirement fails:

reject reason: MARGINAL_VWAP_ACCEPT_FAIL

log once per (date, symbol) via early_reject_logged

continue (skip entry attempt)

does not change counters, day classification, or other guards.

Standard runner used (required)

python scripts\run_range_and_summarize.py ... --scenario B

This TWCS evidence confirms JNVR 2025-04-07 was a legitimate marginal winner, not a “first close above VWAP” junk entry.

Finding from TWCS

The strict rule (“both i-1 and i-2 must close above VWAP”) can be too brittle:

It successfully removes early marginal junk,

but it can also suppress legitimate winners that have real acceptance but not perfectly consecutive i-2/i-1 closes above VWAP at the moment of attempted entry.

Therefore:

v0.8.1.10.0 is directionally correct,

but is an intentionally strict diagnostic version that reveals the next refinement needed.

What v0.8.1.10.0 breaks / over-filters (confirmed by TWCS)

It can suppress legitimate marginal winners (JNVR 2025-04-07) because the strict “i-1 AND i-2 above VWAP” condition is brittle.

Interpretation: what this version represents

v0.8.1.10.0 is a successful diagnostic / structural guard version:

The concept (VWAP acceptance prerequisite on marginal days) is validated across two months.

The strictness level is confirmed to be “too strong” in at least one TWCS-validated winner.

This sets up a single-rule refinement in the next version (v0.8.1.11.0) to preserve the loss removals while allowing delayed acceptance patterns.
