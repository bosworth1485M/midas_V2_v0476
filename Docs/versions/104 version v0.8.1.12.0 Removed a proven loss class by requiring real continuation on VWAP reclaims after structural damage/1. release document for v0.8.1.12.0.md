# Midas_V2 v0.8.1.12.0 — Detailed Version Specification & Validation Record

## Purpose (Executive Summary)

Version **v0.8.1.12.0** strengthens VWAP reclaim entries **after structural damage** by requiring **real continuation**, not a single reclaim candle. The goal is **loss subtraction only**: remove a proven loss class while preserving all existing correct behavior.

This version is **fully A/B validated** against v0.8.1.11.0 across multiple regimes (August, October, November 2025). Results show **material loss reduction in hostile regimes**, **no regression in stable regimes**, and **winner preservation**.

## New Guard Introduced (v0.8.1.12.0)

### Name

**Post‑Damage VWAP Reclaim Continuation Guard**

### Trigger Conditions (Exact)

Runs **only** when all are true:

* `reject_reclaim_after_damage_effective == True`
* `recent_structural_damage == True`
* Structural damage recovery **PASSED** (accepted_above_vwap)
* `blocked == False`

### Rule (Locked)

Using the existing `vwap_map` computed by the structural-damage block:

* Evaluate **completed bars** `[i-1, i-2, i-3]`
* Count bars where:

  * `close > open` (green)
  * `close > vwap_map[j]`
* **PASS** if count ≥ 2
* **FAIL** otherwise → skip entry via `continue`

### Logging (Observability)

Single-line, log-once:

```
[WHY] v0.8.1.12.0 POST_DAMAGE_CONTINUATION_BLOCK symbol={sym} ts={candidate_ts} count={n} window=i-1,i-2,i-3 recovery_passed=True recent_structural_damage=True
```

Reject key preserved:

```
{date}:{symbol}:POST_DAMAGE_CONTINUATION_FAIL
```

## Why This Guard Exists (TWCS‑Driven)

Dominant loss class identified via TWCS inspection:

* Late VWAP reclaim **after structural damage**
* Only **one** reclaim candle
* No follow‑through → stall → stop loss

Representative cases:

* CYRX (2025‑08‑06)
* CNEY (2025‑05‑07)
* Repeated across months

Interpretation:

> *“One green candle after damage is not strength.”*
