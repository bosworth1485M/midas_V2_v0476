# Midas_V2 v0.8.1.12.0 — Detailed Version Specification & Validation Record

## Purpose (Executive Summary)

Version **v0.8.1.12.0** strengthens VWAP reclaim entries **after structural damage** by requiring **real continuation**, not a single reclaim candle. The goal is **loss subtraction only**: remove a proven loss class while preserving all existing correct behavior.

## New Guard Introduced (v0.8.1.12.0)

### Name

**Post‑Damage VWAP Reclaim Continuation Guard**

### Trigger Conditions (Exact)

Runs **only** when all are true:

* `reject_reclaim_after_damage_effective == True`
* `recent_structural_damage == True`
* Structural damage recovery **PASSED** (accepted_above_vwap)
* `blocked == False`

### Rule (Locked)

Using the existing `vwap_map` computed by the structural-damage block:

* Evaluate **completed bars** `[i-1, i-2, i-3]`
* Count bars where:

  * `close > open` (green)
  * `close > vwap_map[j]`
* **PASS** if count ≥ 2
* **FAIL** otherwise → skip entry via `continue`

### Logging (Observability)

Single-line, log-once:

```
[WHY] v0.8.1.12.0 POST_DAMAGE_CONTINUATION_BLOCK symbol={sym} ts={candidate_ts} count={n} window=i-1,i-2,i-3 recovery_passed=True recent_structural_damage=True
```

Reject key preserved:

```
{date}:{symbol}:POST_DAMAGE_CONTINUATION_FAIL
```

Dominant loss class identified via TWCS inspection:

## 4. Design Overview — Blocked-Candidate Diagnostics (TWCS-lite)

### Core Idea

When the system explicitly blocks a trade candidate via a guard (e.g. `POST_DAMAGE_CONTINUATION_BLOCK`), capture **just enough information** to make that decision easy to review later — visually and contextually.

This is **TWCS-inspired**, but **lighter-weight** and **non-invasive**.

---

## 5. What Exactly Gets Captured

For each blocked candidate (log-once per symbol per day):

### Mandatory metadata

* Symbol
* Date
* Time (candidate timestamp)
* Guard name / reject key
* Version tag (v0.8.1.13.0)

### Context snapshot (choose ONE implementation path)

**Option A — Minimal (preferred first pass):**

* Save a small JSON or CSV record per blocked candidate
* Includes:

  * last N completed bars (e.g. 5–10)
  * VWAP values
  * basic bar attributes (O/H/L/C/V)

**Option B — Visual (later refinement):**

* Save a PNG snapshot of the chart window around the block
* Time window: e.g. `t-10min → t+2min`
* Only if this can be done without touching strategy flow

Start with **Option A** unless Option B is trivial in your tooling.
