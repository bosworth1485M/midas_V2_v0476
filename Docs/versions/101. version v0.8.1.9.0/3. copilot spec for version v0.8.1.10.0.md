Marginal-day entry requires prior closes above VWAP (2-bar pre-confirm)
GOAL (EXACT)

Refine marginal-day trading so Scenario B only enters a marginal-day trade after price has already closed above VWAP for multiple candles, while preserving all existing correct behavior.

This version removes a specific failure class observed in TWCS (e.g., GRI 2025-04-01) without affecting hostile/healthy days.

NEW RULE TO ADD (EXACT)
When the new rule applies (MANDATORY)

Run this check only when all are true:

require_day_follow_through == True (DAY_GATE is enabled)

close_gt_vwap_count == 1 (day is marginal)

day_trade_count < 1 (marginal-day trade still allowed)

Entry is otherwise being considered at the current bar index i (i.e., right before the existing combined entry condition)

If any are false, do not run the rule.

What the rule enforces (MECHANICAL)

Before allowing entry on a marginal day:

Let i be the index of the candidate entry candle in the minute-bar series.

If i < 2, fail closed (reject entry via this rule) because there are not enough prior candles.

Examine the two most recent completed candles immediately before entry: indices i-1 and i-2.

Both candles must satisfy all of the following:

close > open (green)

close > vwap_at_that_bar

If either candle fails either condition → reject the entry.

VWAP CALCULATION (CRITICAL CODE REALITY — MUST MATCH EXISTING LOGIC)

Do NOT rely on bar.vwap being present/populated.

Compute vwap_at_that_bar for i-1 and i-2 using the same incremental PV/V method used elsewhere in this codebase (DAY_GATE / VWAP checks):

For each bar k, compute typical price: tp = (high + low + close) / 3

Maintain running sums from bar 0 through bar k:

cum_pv += tp * volume

cum_v += volume

vwap_k = cum_pv / cum_v (only if cum_v > 0, else treat as unavailable and fail closed)

You may compute VWAP up to i-1 and i-2 locally inside the entry check in a minimal way (no refactor, no helper functions).

Fail closed if VWAP cannot be computed.

REJECTION BEHAVIOR

When the rule rejects an entry:

Do NOT change day_trade_count

Do NOT change effective_day_gate_failed

Do NOT change any other guard behavior

Use existing early-reject log framework

Reject reason (EXACT STRING)
MARGINAL_VWAP_ACCEPT_FAIL

Logging (log-once)

Log once per symbol per day using early_reject_logged (same pattern as other EARLY_REJECT reasons). Include:

a brief note that i-1 and/or i-2 did not meet “green + close_above_vwap”

Do NOT print arrays. Keep it short.
