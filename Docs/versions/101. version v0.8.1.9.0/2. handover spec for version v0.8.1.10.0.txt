6. TWCS Analysis Performed (Critical Evidence)

Per workflow rules, TWCS was used as the primary diagnostic tool.

Marginal-day LOSS (failure case)

GRI — 2025-04-01 — SL −34.88 (−2.5%)

Observed via TWCS:

Entry occurred when the entry candle was the first candle to close above VWAP

There were no completed candles closing above VWAP prior to entry

Price failed to remain above VWAP and stopped out quickly

This trade exists only because v0.8.1.9.0 allowed one marginal-day trade.

Marginal-day WIN (success case)

JNVR — 2025-04-07 — TP +27.93 (+2.0%)

Observed via TWCS:

Multiple completed candles closed above VWAP before entry

Price remained above VWAP

Trade showed clean continuation into profit

This is a valid marginal-day opportunity that the feature was intended to capture.

7. Root Cause Identified

v0.8.1.9.0 currently:

uses day-level classification (marginal day)

applies a one-trade-per-day cap

This is necessary but insufficient.

It does not distinguish between:

marginal-day entries where price has not closed above VWAP before entry (GRI), and

marginal-day entries where price has already closed above VWAP for multiple candles (JNVR).

8. Key Principle Derived (From TWCS)

On marginal days, a trade should not be entered until price has already closed above VWAP for more than one completed candle.

This principle was derived from observed behavior, not from theory or optimization.

9. Anticipated Improvement in v0.8.1.10.0
Why improvement is expected

The next version will remove a specific, proven failure class (early marginal-day entries before price has held above VWAP).

This is expected to improve results because:

the losses introduced in v0.8.1.9.0 are not random

they cluster around entries made before price showed persistence above VWAP

Removing these trades improves trade quality, not trade frequency.

Expected impact on win rate

Marginal-day win rate is expected to increase

Because:

low-probability entries (GRI-type) are removed

high-probability entries (JNVR-type) are preserved

Overall win rate may improve modestly; marginal-day win rate should improve more clearly.

Expected impact on profit / expectancy

Expectancy on marginal days is expected to improve

Even if total trade count decreases slightly

Removing a −2.5% loss while preserving +2.0% wins materially improves average outcomes per marginal trade.

This is how profitable Cameron-style systems typically improve:

They remove bad trades rather than adding more trades.

What is not expected

The next version is not expected to:

increase total trade count

materially change results on hostile or healthy days

eliminate all losses

outperform strongly trending months by itself

It is a risk-quality improvement, not a growth lever.

10. Objective of v0.8.1.10.0

Refine marginal-day participation so that:

trades are allowed only after price has already closed above VWAP for multiple candles

all existing correct behavior remains unchanged

This refinement should:

block GRI-type failures

preserve JNVR-type winners

add exactly one structural condition (no refactors, no new indicators)
