Midas_V2 v0.8.1.9.0
Limited Marginal-Day Participation (1 trade max) — strict A/B validation
GOAL (EXACT)

Enable limited marginal-day participation for Scenario B when DAY_GATE is enabled:

Hostile days (close_gt_vwap_count == 0): no trades (unchanged)

Marginal days (close_gt_vwap_count == 1): allow at most 1 completed trade for the entire day

Healthy days (close_gt_vwap_count >= 2): unchanged (normal behavior)

This version MUST be:

deterministic

reversible

minimal

enforced at entry time (not by changing DAY_GATE computation)

This change exists ONLY so we can run strict A/B validation over wide ranges using run_range_and_summarize.py with logs written to files.

CRITICAL CODE REALITY (DO NOT RE-IMPLEMENT)

In backtester.py, entries only occur behind:

if (not day_gate_failed) and position is None and pending_entry is None and strat.should_enter(...) ...

Therefore, on many “marginal” days where:

close_gt_vwap_count == 1, but

day_gate_failed == True (common when min_symbols=2 and only 1 qualifies),

no entry is possible, even if you add a “1 trade max” counter.

So v0.8.1.9.0 MUST introduce a minimal mechanism to override enforcement of day_gate_failed for marginal days at entry time, without changing how day_gate_failed is computed.
