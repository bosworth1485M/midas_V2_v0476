1. Why This Version Exists

This version addresses two foundational problems discovered during TWCS review and multi-month backtesting:

Execution realism flaw
Some trades were entered even though the confirmation candle itself already violated the stop intrabar. These trades appear valid in bar-based backtests but would be instantly stopped in live execution.

Silent trade suppression
When trades disappeared (including entire 0-trade days), the backtester provided no explanation, forcing guesswork and undermining confidence.

The execution fix (originally developed as v0.8.1.8.0) and the observability work (v0.8.1.8.1) are inseparable. Because v0.8.1.8.0 was never released independently, both are consolidated and documented as v0.8.1.8.1.

3. What Changed (and What Did Not)
3.1 Functional change — execution safety

Confirm-bar stop-violation guard

At confirmation time, inspect the wick-correct candle.

If intrabar price action would already hit the stop:

Reject the trade.

Emit a [WHY] CONFIRM_BAR_STOP_VIOLATION log.

This enforces live-trading realism and removes structurally invalid entries.

3.2 Observability changes — no behavior change

Added explicit [WHY] EARLY_REJECT logs at all early rejection paths in backtester.py, including:

DAY_GATE_FAILED

STRUCT_DAMAGE_FAIL

VWAP_MISSING

DAILY_MAX_LOSS

MAX_TRADES_PER_SYMBOL

Enhancements include:

Log-once latch (per symbol / per reason / per day)

Contextual details= fields using existing variables only

Version-consistent log stamping

These changes do not alter trading behavior.

3.3 Explicit non-changes

❌ No indicator logic modified

❌ No thresholds adjusted

❌ No entry logic loosened

❌ No exits or sizing changed

❌ No new filters introduced

❌ strategy.py restored to its exact pre-version state

5. Validation Methodology

Validation was intentionally performed across three time-diverse market regimes:

Period	Regime Type	Purpose
April 2025	Hostile / choppy	Stress execution safety
July 2025	Marginal / mixed	Diagnose trade suppression

All tests used:

6. April 2025 Results (Hostile Regime)
Command
python scripts\run_range_and_summarize.py --start 2025-04-01 --end 2025-04-10 --scenario B

Observations

Very low trade count

Multiple STRUCT_DAMAGE_FAIL

Several CONFIRM_BAR_STOP_VIOLATION events

Conclusion

April contained structurally weak setups and confirmation candles that already violated stops.
The confirm-bar guard correctly filtered execution-invalid trades.

9. Conclusions on Profitability
9.1 Why profit is currently low

Profitability is lower than desired due to unwanted side effects of conservative controls introduced for correctness:

DAY_GATE is binary and aggressive, suppressing entire marginal days

Trade count is significantly reduced

Winning trades are not amplified (conservative exits, no re-entries, flat sizing)

These effects were accepted temporarily to eliminate execution errors and ambiguity — not because low profit is acceptable.

9.2 What is not causing low profit

Based on evidence:

❌ No execution bugs

❌ No silent trade suppression

❌ No confirm-bar guard overreach

❌ No unstable or random behavior

Low profit is therefore structural and temporary, not accidental.

9.3 Interpretation of the current phase

v0.8.1.8.1 represents a necessary but incomplete phase:

execution correctness achieved

observability achieved

profitability not yet achieved

This phase is a prerequisite — not the destination.
